# PoWh 月度统计 · 例行校验清单

> **用途**：每次月度 PoWh 统计**开始前必须先跑**本清单；跑完填「本期结论」再入表。
> **性质**：只读校验。不改任何原始记录、不改飞书表、不改审计报告、不发布、不写组织仓库。
> **创建**：2026-09-20 ｜ 触发：8 月统计出现「审计名单未过滤」漏检 ｜ 执行：小采（AI 辅助）
> **取证分级**：A=仓库/接口实测｜B=规范或官方文本原文｜C=推断｜D=不可得
> **🔴 隐私**：全文只以 **J-N** 标识，不含姓名/昵称/handle/地址↔人名映射。

## 〇｜必检项【🔴 优先级最高】

### 【必检项】节点审计名单过滤

> **教训来源**：8 月统计所依据的**审计报告正文名单**含 3 个「审计未通过」节点（J-5 / J-24 / J-43），该漏检需在每期前置拦截。

| 步 | 动作 | 判据 / 出处 |
|---|---|---|
| ① | 取**当期**节点审计报告 | `Jouleverse/workspace` **issue#2** 评论区**当期**《YYYY年M月 节点统计》（含第 3 节「审计未通过/已退出」）｜`gh api "repos/Jouleverse/workspace/issues/2/comments?per_page=100"` |
| ② | 取**当期统计所用的有效节点名单** | 统计所用表（飞书）`主网记账(个)` / `主网见证(个)` 两列；或当月底稿 |
| ③ | **逐项核对**：名单中是否存在「未通过审计」的节点 | 以报告**第 3 节**清单 × 第 1/2 节正文名单**求交集**；交集非空即命中 |
| ④ | 若有 ⇒ **必须剔除**，未通过审计者**不得**进入统计范围 | 命中项 WP-2 一律**清零**（记账 slash 0.5h / 见证 slash 0h **亦不计**）｜依 spec 2.6 + 报告第 3 节 |
| ⑤ | 剔除后**核对节点总数 / 记账数 / 见证数**是否与报告一致 | 记账 = 报告第1节正文数 − 其中未通过数；见证同理；三者须自洽（相加 = 总数） |
| ⑥ | **记录本期结论**（剔除数与依据） | 写入本期「例行校验结论」段；无剔除亦须写「无」 |

**⚠️ 衍生子检查**：
- **③-a 小标题 vs 正文计数一致性**：报告各节**小标题计数**须与**正文实列行数**一致；不一致须记录（8 月：小标题 16/26 vs 正文 15/27，正文自洽于「共计 42」）。
- **③-b 两类状态区分**：「审计未通过」与「**已退出**」在正文名单中的处理须分别确认（往月对「已退出」者曾移出正文名单）。
- **③-c `slash` 与「剔除」叠加**：未签到 slash 后的残余值（记账 0.5h）**不因 slash 而保留**，剔除即清零。

### 【必检项·数据源独立性声明】

> **要求**：每次统计产出时，**必须在报告开头写明**下列三项。

| # | 必须写明的内容 |
|---|---|
| ① | **本次计算的数据源清单**（issue 编号、链上数据、纪要、稿件等，逐项列出） |
| ② | **明确声明**：结果系依据 **spec 规则独立算出**，对照表**仅用于比对**，**【未读取对照表回填】** |
| ③ | **例外显式标注**：若某月因故**无法独立取数而改用表内数字**，**必须显式标注**，且**该月结果不得计入信任基线** |

**报告开头固定声明模板**：

```
【数据源独立性声明】
本次计算数据源：<issue#N …／链上 CheckIn（合约、块窗）／纪要 <路径>／稿件 <路径> …>
独立性声明：本结果系依据 spec 规则、基于上述原始证据独立算出；
  对照表（<载体>）仅用于比对，【未读取对照表回填】。
例外标注：<无 ／ 本月经因 ___ 改用表内数字，本结果不计入信任基线>
```

**判定（自查问法）**：本报告每个数字，是否都能追到**上游原始凭据**而非对照表单元格？若有一个数字**只能**来自对照表 ⇒ 该月**触发第 ③ 项标注**。

## 〇-2｜永久规则（🔴 长期生效，无需每期重新明示）

> 以下六条为 **J-53 固化指令（2026-09-24）**，长期生效；与「必检项」同属**前置**性质，**每期必须先过**。

| 编号 | 规则 | 要点 | 状态 |
|---|---|---|---|
| **规则 A** | **未通过审计的节点 ⇒ 一律【删除整行】**，不进入统计名单 | 不得仅清零 WP-2 而保留行；**整行移出** | 永久 |
| **规则 B** | **分母 Σh = 录入表【合计行】的值** = 表内在册人员所有 WP 项 h 之和 | **h=0 者计入**（加 0 不影响）；**已删除者不计入**；⇒ Q2 关闭 | 永久 |
| **规则 C** | **同一凭据（同一 issue / 同一次产出）只能归入【一个】WP 项**，不得重复计入 | 归入**最贴近项**，并在 **raw 中注明理由** | 永久 |
| **规则 D** | **未过审者整行删除**；**在册但 h=0 者保留列示 0.00** | ⇒ Q4 关闭 | 永久 |
| **规则 E** | **建 PR 前必须显式核对 base repo**；**默认一律指向【个人 fork】**，禁止默认指向组织仓库 | 指向前先验 `base.repo`；**不得** POST 到 `Jouleverse/*` | 永久 |
| **规则 F** | **计数列（记账/见证「个」）与工时列（h）严禁混加** | 「个」为计数，「节点有效汇总」才是 h；两列不得相加 | 永久 |
| **规则 G** | **遇到规则不明确/判据不清/不知如何归类 ⇒ 先去查看并学习【飞书人工统计表格】的做法，以人工表既有处理方式为参照** | 人工表为多年实践形成的口径，**优先于推断**；采用时须在 **raw 中注明「依飞书人工统计表 X 处做法」**；若人工表也无先例或与 spec 冲突 ⇒ **停下回报，不自行发明规则**。⚠️ 飞书表**仅作口径参照**，仍须**独立取数计算**；**严禁读取对照表数字回填** | 永久 |
| **规则 H** | **零贡献列 ⇒ 整个 WP 列删除（表头 + 全列数据）** | 逐列检查**所有在册人员**数值；**全部为 0 ⇒ 删除该列**；**只要有任一人 > 0 ⇒ 保留**；合计行、脚注、执行对账表**同步更新**。**自 2026-08 起**适用，后续月份沿用；**raw 明细不受影响**（仍保留全部逐条凭据） | 永久（自 2026-08） |
| **规则 I** | **激励公式一律用规范式：`个人 WJ（万WJ）= ROUNDDOWN( h ÷ Σh × 1200, 2 )`**；**每月激励池 = 1200 万WJ（恒定）**；尾差 = **Σ被舍去的第三位小数 = 1200 − Σ实发**，**归创世金库**；**所有金额与尾差表述必须带单位** | 旧式 `FLOOR(…×120000,1)/100` **与之等价、沿用不致误**，但规范式**直观体现池值 1200**（120000 = 1200×100）；池值调整 ⇒ 直接写 X，**不得改动两位小数截断部分** | 永久 |

**规则执行要点**：

- **A / D 联动**：命中审计未通过 ⇒ **整行删除**（非置零保留）。因此 h=0 且**在册**者（如当月未签到但已过审）**保留**并列 0.00；**未过审者**则**不出现**在表中。
- **B 自洽校验**：录入表**合计行**值 = 各行「合计」之和 = 各 WP 列纵向之和；三者须一致，否则停机（对应校验 §三 第 19–21 项）。
- **C 落地方式**：raw 逐条凭据表中，每条须可唯一归属；若同一 commit / PR / issue 被两个 WP 引用 ⇒ **停机**，按「最贴近项」归一并注明理由。
- **E 硬动作**：`gh pr create` / `gh api POST .../pulls` 前，先确认目标 `base.repo.full_name` **为个人 fork**；**严禁**指向 `Jouleverse/*`。
- **F 记忆点**：表中「主网记账(个)」「主网见证(个)」两列**仅为计数**，其对应工时已包含在「WP-2 节点有效汇总(小时)」列内；**相加即错**。
- **G 双轨不冲突**：人工表作**口径参照**（归类/取舍模板），数据仍须**从原始凭据独立取数**；两事并行，不得以「参照」为由抄录对照表数字。
- **H 删列范围**：仅指 **WP 贡献列**（如 WP-4 社群）；「链上签到」「主网记账(个)」「主网见证(个)」「合计」「占比」「激励额度」**不属可删范围**。
